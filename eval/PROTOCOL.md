# 분석 계획 — 네 방식 비교 (2026-11-03 고정, 기한은 11/9)

이 문서는 11/3 에 고정했다(태그 `eval-freeze-2026-11-03`, 해시 목록 `freeze/H0-2026-11-03.txt`). 그 뒤에 바꾼 것은 지우지 않고 맨 끝 편차 표에 적는다.
"11/30 에 정한다"고 적은 값은 도구를 고정하는 날 H1 기록에 적는다. 10/7 에 쓴 초안(정적 도구 하나를 재는 계획)을
방향 A 에 맞게 고쳐 쓴 것이다.

## 1. 질문

연구계획서의 질문을 그대로 쓴다. **정적 분석과 AI 검토를 결합하면 결과의 정확성과 이해도가 어떻게 달라지는가.**

비교하는 방식은 넷이다. 모두 같은 도구 커밋, 같은 정책 6개, 같은 저장소 표본에서 돈다.

| | 방식 | 실행 |
|---|---|---|
| M1 | 정적 단독 | `--judge none`. 모델 호출 0회 |
| M2 | 정적 + AI 재검토 | 정적으로 '모름'인 곳만 파일 하나를 보여 주고 묻는다(지금 있는 판정기) |
| M3 | AI 독립 검토 | 정적 신호 없이 AI 가 의무 설명과 저장소를 받아 스스로 찾고 판단한다 |
| M4 | 결합(방향 A) | 정적 신호와 저장소 색인으로 후보를 만들고, AI 가 여러 파일을 읽어 판단하고, 인용 관문을 거친다 |

11/30 까지 M3 나 M4 가 돌지 않으면 그 방식은 "재지 못함"으로 적고 나머지만 비교한다. 다른 방식으로 바꿔 넣지 않는다.

## 2. 가설과 지표

**주 가설은 하나다.** H1: 쌍 단위 F1 에서 M4 가 M1 보다 높다. 저장소 부트스트랩(2,000회, 짝지은 비교)으로 낸
F1 차이의 95% 구간이 0 을 넘으면 지지, 0 을 포함하면 "차이를 보이지 못함"으로 적는다.

부 지표는 모두 서술로 내고 구간을 붙인다. 여러 개를 재므로 이것들로 "유의하다"는 말을 쓰지 않는다.

- 방식마다 쌍 단위 정밀도·재현율·F1, 단위(시작 파일) 단위 정밀도·재현율.
- M4 − M2: 여러 파일을 읽는 것이 파일 하나를 읽는 것보다 나은가(재현율 차이).
- M4 − M3: 정적 신호와 인용 관문이 AI 단독보다 오경보를 줄이는가(정밀도 차이), 비용은 어떤가.
- 근거 불일치율: AI 가 낸 인용 가운데 관문이 거절한 비율(M2~M4).
- 비용: 저장소당 모델 호출 수, 입력·출력 토큰, 걸린 시간, 금액.
- 사람이 본 경고의 정밀도(7절), 사람과 LLM 라벨의 일치(카파), 두 LLM 라벨러 사이의 일치(카파).
- 이해도(작게): 개발자 3~5명에게 같은 경고를 M1 꼴과 M4 꼴로 보여 주고 "무엇을 고칠지" 답하게 한 정답률.
  사람 수가 적어 서술만 한다.

## 4. 단위와 정답

### 단위

- 단위는 (시작 파일, 정책)이다. 시작 파일은 policypack 이 검사 대상으로 고르는 JS/TS 파일이다.
- 출처는 셋이다.
  - **선별(screened)**: `guide/screen.json` 의 낱말 묶음에 모두 걸린 파일. 저장소·정책마다 4개까지, 넘으면 추첨
    난수로 정한 순서의 앞에서부터(`scripts/units.py`). 상한을 4로 둔 까닭: 9/30 dev 저장소 20곳에 이 낱말을 대 보니
    상한 8이면 저장소당 19.0단위, 4면 12.5단위였다. 주 지표가 쌍 단위라 쌍마다 양성 단위 하나만 찾으면 되고,
    라벨 한 건이 여러 파일을 읽는 대화라 비용이 단위 수에 비례한다.
  - **선별 밖(unscreened)**: 저장소마다 어느 정책에도 걸리지 않은 파일 하나. 선별이 놓친 양성을 어림한다.
  - **경고(flagged)**: 네 방식 가운데 하나라도 경고를 냈는데 아직 라벨이 없는 (파일, 정책). 스캔 뒤에 더한다.
    정밀도에만 쓰고 재현율의 분모에는 넣지 않는다(9/30 dev 재현율 0.52 가 이 구분 없이 부풀려진 값이었다).

### 정답

- 라벨러는 시작 파일에서 시작해 **같은 저장소의 다른 파일을 읽기 전용으로 찾아 읽고** 값을 붙인다. 의무는 서비스와
  흐름에 붙기 때문이다(고지는 약관 화면에, 나이 확인은 가입 앞 단계에 있을 수 있다). 묻는 것과 값의 뜻은
  `guide/LABEL_GUIDE.md` 가 정한다.
- 값: 검토 필요 / 충족 근거 있음 / 해당 없음 / 가를 수 없음. 근거는 (파일, 줄, 원문) 인용으로 남긴다.
- 라벨러는 기준서의 한국어 값을 답한다. 실행 스크립트가 채점용 이름으로 옮긴다: 검토 필요 → `needs-review`,
  충족 근거 있음 → `compliant`, 해당 없음 → `not-applicable`, 가를 수 없음 → `unsure`. 범위 표시는 기준서의 글자를
  그대로 `scope` 에 둔다("없음"은 비운다).
- 기준서·선별 낱말·라벨러 프롬프트는 도구를 만드는 세션이 쓰지 않았다. 조문 원문과 지시문만 받은 별도 에이전트가
  썼고(`guide/`), 받은 그대로 고정한다. 지시문은 `guide/BRIEF.md` 에 있다.

### 쌍

- 쌍은 (저장소, 정책)이다. 라벨이 붙은 단위 가운데 '검토 필요'가 하나라도 있으면 양성, 하나도 없으면 음성이다.
- 방식이 그 저장소·정책에 경고(검토 필요 또는 모름)를 하나라도 내면 그 쌍을 경고한 것으로 본다.
- 정밀도 = 경고한 쌍 가운데 양성 / 경고한 쌍 가운데 정답이 있는 쌍.
  재현율 = 도구와 무관한 단위(선별·선별 밖)로 양성이 된 쌍 가운데 경고한 쌍. `scripts/compare.py` 가 이렇게 센다.
- 쌍을 주 단위로 삼는 까닭: 의무는 서비스에 붙고 같은 저장소의 파일들은 서로 독립이 아니다. 또 M3·M4 는 흐름의
  진입 파일을 스스로 고르므로, 파일이 정확히 같아야 맞힌 것으로 치면 방식 사이의 비교가 어긋난다.
  쌍 단위는 엉뚱한 파일에 낸 경고도 맞힌 것으로 칠 수 있어서, 단위 단위 정밀도(경고한 파일마다 라벨)를 함께 낸다.

### 범위가 갈리는 곳 — 표를 미리 정한다

라벨러는 값과 따로 범위 표시를 붙인다(`guide/LABEL_GUIDE.md`). 결과를 본 뒤에 유리한 칸을 고르지 않도록
모든 칸을 낸다.

| | 나이를 받지 않는 가입(22-2) | 시험·스토리 파일 |
|---|---|---|
| **주 칸** | 해당 없음으로 본다(`na`) | 해당 없음으로 본다(`na`) |
| 대조 칸 | 라벨러 값 그대로(`keep`) | 라벨러 값 그대로(`keep`) |
| 뺀 칸 | | 단위를 뺀다(`drop`) |

10/7 초안의 "서버 전용 파일" 칸은 없앤다. 방향 A 에서는 서버 파일의 의무도 저장소 전체를 보고 판단하기 때문이다.
주 칸은 `--scope "나이를 받지 않는 가입=na" --scope "시험·스토리 파일=na"` 이다. 기준서는 두 표시가 함께 맞으면
"시험·스토리 파일"을 붙이게 한다.

## 7. 사람이 보는 것

- 감사 표본(`scripts/audit_sample.py`): 네 방식 경고의 합집합에서 최대 60건(정책별 층화) + 경고가 아닌 단위 60건
  (LLM 라벨 양성 30건, 그 밖 30건). 출처를 지우고 섞는다. 어느 방식이 냈는지는 열쇠 파일에만 둔다.
- 소유자(규칙 작성자)는 감사 표본 전체를 도구 출력 없이 본다. 자기 라벨의 해시(H4)를 보낸 뒤에만 열쇠를 연다.
- 규칙 작성자가 아닌 사람이 그 가운데 무작위 30건(경고와 비경고 1:1)을 본다.
- "자기 평가"라는 말을 떼는 조건: 비작성자 30건 이상, 경고와 비경고가 섞임, 일치도를 보고, 갈린 건은 비작성자의
  값으로 채점. 못 미치면 제목에 "자기 평가(비작성자 표본 n건 일치도 병기)"를 단다.

## 8. 모델과 비용

- 라벨러: 두 라벨러는 서로 다른 모델이다(A: `claude-opus-5-5`, B: `claude-sonnet-5-5`). 갈리면 A 와 같은 모델이
  두 답과 근거를 보고 정한다. 판정기(M2~M4)의 모델은 11/30 에 정하고, 라벨러와 같은 모델이면 한계에 적는다.
- 라벨러는 저장소 밖을 읽지 못하는 읽기 전용 도구 셋(파일 목록, 파일 읽기, 검색)만 쓰고, 단위당 30번까지 부른다.
- 비용 상한은 10~11주에 9/30 dev 저장소로 라벨러와 M3·M4 의 저장소당 비용을 잰 뒤 11/30 에 정한다.

| M1 쌍 F1 | 0.35~0.50 | 9/30 test 를 `compare.py` 로 다시 세면 0.48(저장소 18곳). 새 표본은 흐름 양성이 더 많을 것 |
| M2 쌍 F1 | M1 과 비슷(±0.05) | 9/30 test 에서 M2 − M1 = −0.05. 판정기는 정밀도만 올리고 재현율은 그대로였다 |
| M4 쌍 F1 | 0.55~0.70 | 놓친 양성 21건 가운데 15건이 파일 하나만 보는 구조 때문이었다(중간 평가) |
| M3 정밀도 | M4 보다 0.1 이상 낮음 | 인용 관문과 정적 신호가 없으므로 |
| 양성 쌍 수 | 30~50 | 9/30 test: 저장소 18곳에 양성 쌍 12개. 이번 표본은 저장소 수가 세 배 남짓 |

## 11. 한계 (보고서에 그대로 적는다)

- 재현율의 정답은 LLM 라벨이다. 사람이 본 것은 감사 표본뿐이다.
- 라벨러도 AI 이고 저장소를 읽으며 판단한다. M3·M4 와 같은 회사의 모델이다. 서로 다른 모델 둘을 쓰고 사람 감사로
  확인하지만, 같은 계열 모델끼리의 공통 오류는 남는다.
- 기준서는 도구를 만드는 세션과 다른 에이전트가 썼지만, 같은 계정에서 같은 회사의 모델이 썼다. 격리는 지시와
  입력 폴더로만 지켰다.
- 모집단은 한국어 설명이 붙은 공개 저장소이고 학습·팀 프로젝트가 많다. 운영 서비스를 대표하지 않는다.
- 광고 보류분은 무작위 추출이 아니다.
- 선별 낱말에 걸리지 않은 파일의 양성은 저장소당 한 단위의 표본으로만 어림한다.
- "라벨이 먼저, 실행이 나중"과 고정 시각은 커밋·태그의 기록으로만 보인다. 제3자가 시각을 확인해 주지 않았으므로
  고정 시점은 작성자의 기록을 믿어야 한다.
