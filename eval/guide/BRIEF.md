# 라벨 기준서 지시문 (2026-11-03)

이 지시문은 도구(policypack)를 만드는 세션이 썼다. 기준서는 그 세션이 쓰지 않는다. 정답 기준이 도구의 규칙이나
프롬프트를 닮지 않게 하려는 것이다. 이 폴더(`legal/` 의 조문 원문 7개와 이 파일)만 가진 별도 에이전트가 쓴다.

## 지시문

이 폴더의 `legal/` 에 한국 법 조문 원문이 있다. 이 조문들만 보고, 공개 JS/TS 저장소에 라벨을 붙일 기준서를
한국어로 써 달라. 이 폴더 밖의 파일은 열지 말고, 웹 검색도 하지 않는다.

### 단위와 질문

- 단위는 **(시작 파일, 정책)** 이다. 시작 파일은 의무가 걸릴 만한 처리가 있을 수 있는 코드 파일 하나다.
- 라벨러는 시작 파일을 먼저 읽고, **같은 저장소의 다른 파일을 읽기 전용으로 찾아 읽을 수 있다**(파일 목록, 파일 읽기,
  글자 검색). 의무를 이행하는 처리는 다른 파일(약관 화면, 가입 단계, 공통 컴포넌트, 서버 미들웨어 등)에 있을 수 있다.
- 묻는 것: "이 시작 파일에서 일어나는 처리에 대해, 이 저장소의 코드를 보면 조문의 의무를 이행하는 처리가 보이는가".
  법 위반 여부를 묻는 것이 아니다. 저장소 밖(운영 중인 웹사이트, 별도 문서, 사업자의 실제 계약)은 없는 것으로 본다.
- 값은 넷이다. 라벨러는 늘 이 넷 가운데 하나를 고른다.
  - 검토 필요: 의무가 걸리는 처리가 시작 파일에 있는데, 저장소 어디에서도 이행하는 처리가 보이지 않는다
  - 충족 근거 있음: 의무가 걸리는 처리가 있고, 이행하는 처리가 저장소에 보인다
  - 해당 없음: 시작 파일이 그 의무가 걸리는 처리를 하지 않는다
  - 가를 수 없음: 코드만으로 정말 가를 수 없다(되도록 쓰지 않는다)
- 근거 인용: '검토 필요'는 의무가 걸리는 처리의 코드 줄을, '충족 근거 있음'은 이행하는 처리의 코드 줄을 하나 이상
  (파일 경로, 줄 번호, 코드 원문 그대로)로 적는다. 다른 파일에서 찾은 근거면 그 파일을 적는다.
  주석과 문서(README 등)는 실행되는 처리가 아니다. 다만 화면에 보이는 문구(JSX 텍스트, 약관 본문 문자열)는 처리다.

### 값과 따로 붙이는 표시

- 범위 표시(하나만): 나이를 받지 않는 가입(정책 kr.pipa.22-2 에서, 생년월일·나이를 받지 않는 일반 가입) /
  시험·스토리 파일(*.test.*, *.spec.*, 스토리북, 목업 데이터) / 없음. 표시가 붙어도 값은 "그 단위가 범위 안이라면
  무엇인가"로 적는다. 범위에 넣을지는 채점 때 정한다.
- 논쟁 있음: 해석이 갈릴 수 있다고 보는 단위. 왜 갈리는지 한 줄.

### 주의

- kr.network-act.50-4 의 세부(표기 방식, 앱 푸시의 명칭과 수신거부 방법)는 조문이 시행령 별표에 맡기는데 그 별표
  원문이 여기 없다. 조문에서 읽히는 것만 적고 "잠정"이라고 표시한다.
- kr.pipa.ai-transfer 는 조문 발췌만 있다. 발췌에서 읽히는 것만 쓰고, 읽히지 않는 것(시행령의 공개 방법 등)은
  "발췌 밖"이라고 적는다. 외부 AI 서비스가 국외 사업자인지는 코드의 API 주소·SDK 이름으로만 판단한다.

## 내 달라는 것 (이 폴더의 `out/` 에)

1. `LABEL_GUIDE.md` — 원칙, 값의 뜻, 정책마다 "의무가 걸리는 처리"와 "이행하는 처리"를 조문의 말로 설명하고, 코드에서
   어떻게 보이는지 예를 든다. 헷갈리기 쉬운 경우의 판정 예를 정책마다 셋 이상. 다른 파일에서 근거를 찾을 때 어디까지
   찾아야 하는지(찾기를 멈추는 기준)도 정한다.
2. `screen.json` — 정책마다 라벨할 시작 파일을 고르는 낱말 묶음. 조문의 개념에서 뽑는다(예: 가입, 생년월일).
   형식: `{ "<정책 id>": [[낱말, ...], [낱말, ...]], ... }`. 파일이 모든 묶음에서 낱말을 하나 이상 가지면 고른다.
   낱말은 대소문자를 가리지 않는 정규식이고, 한국어와 영어 코드 이름을 함께 쓴다. `_note` 키에 고른 원칙을 적는다.
3. `labeller-prompt.md` — 라벨러 모델에게 줄 지시문. 저장소 하나, 시작 파일 하나, 정책 하나를 주고, 읽기 전용 도구
   셋(list_files, read_file, search)을 쓸 수 있다. 도구는 단위당 30번까지. 답은 JSON 하나:
   `{"label": ..., "citations": [{"file": ..., "line": ..., "text": ...}], "scope": ..., "disputed": null 또는 이유,
   "reason": 한 줄}`. 프롬프트에는 기준서의 해당 정책 부분을 넣는 자리(`{{POLICY_SECTION}}`)를 둔다.
