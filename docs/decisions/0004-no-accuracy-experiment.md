# 0004 정답지를 만드는 정확도 실험(네 방식 F1 비교)을 하지 않는다

- 상태: 채택
- 날짜: 2026-11-05

## 배경

10/24 에 계획한 평가는 공개 저장소 66곳에 정답(라벨)을 붙이고 네 방식(정적 단독, 정적 + AI 재검토, AI 독립,
결합)의 F1 을 비교하는 것이었다. 11/3 에 라벨 기준서, 표본 추출, 분석 계획을 고정했다(태그 `eval-freeze-2026-11-03`).

사람이 라벨을 붙일 시간이 없어 정답을 LLM 라벨러 둘이 붙이기로 했는데, 그러면 실험이 잴 수 있는 것은
"도구가 비싸고 꼼꼼한 AI 검토를 얼마나 따라가는가"뿐이다. 도구가 라벨러보다 나은 곳은 오답으로 채점된다.
라벨러와 도구가 같은 모델을 쓰면 점수가 부풀려진다. dev 예행에서도 sonnet 이 붙인 정답에 sonnet 재확인이
점수를 올렸다. 라벨 비용은 보수 단가로 약 $440 이었다.

## 결정

정답지를 만드는 정확도 실험을 하지 않는다. `eval/`(고정 문서, 라벨러·채점 도구)와 `docs/evaluation.md` 를
지웠다. 기록은 태그 `eval-freeze-2026-11-03` 과 그 뒤 커밋(`902c715` 까지)에 있다.

프로젝트의 의의는 동작하는 시스템에 둔다: 국내 법 의무 지도 → 정책 팩 → 인용을 요구하는 AI 에이전트 검토 →
CLI·CI·웹 서비스. 결과 보고서에는 정답 없이 도구 출력에서 바로 세는 것만 싣는다.

- 인용 관문이 거절한 AI 근거의 비율(코드에 없는 근거로 경고를 지우지 못한 수)
- 외부로 보내기 전에 가린 비밀값 수, 읽지 않은 비밀 파일 수
- 저장소당 비용·시간·모델 호출 수
- 공개 저장소 사례 몇 개: 정적 검사만으로는 보지 못하고 여러 파일을 읽어 찾은 곳, AI 가 인용으로 푼 곳

## 결과

- "정확도가 얼마인가"에 답하지 않는다. 결과 보고서의 한계 절에 이 결정과 까닭을 적는다. 연구계획서의 연구
  질문 가운데 정확성 부분은 사례로만 보인다.
- 정확도 수치를 홍보 문구에 쓰지 않는다. dev 예행의 수치는 AI 라벨 기준의 참고치라 내세우지 않는다.
- 사람이 검수할 시간이 생기면 사례 리포트를 읽고 맞는지 보는 것부터 한다(정답지 없이도 된다).
