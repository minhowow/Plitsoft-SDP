# 0001 점검 대상을 국내 법·정책 의무로

- 상태: 채택 (지도교수·멘토 확인 대기)
- 날짜: 2026-09-17 정함, 2026-10-24 기록

## 배경

계획서는 JS/TS 보안·품질 이슈 8유형을 필수 범위로 두었다. 9월 조사에서 플랫폼이 커밋 전 AI 보안 리뷰를 무료로
주고(Claude Code, Copilot, Codex), Semgrep Registry 규칙은 재배포가 금지돼 있으며, 일반 보안 규칙은 이미 여러
도구가 다룬다는 것을 확인했다. 같은 규칙을 다시 쓰면 좁고 덜 다듬어진 재구현이 된다.
산업체 제안(플리트소프트 #5)은 "보안 중심이되 정책·법·기획 관점도"를 적었다.

## 결정

점검 대상을 국내 법령에서 코드에 흔적이 남는 의무로 바꾼다. 개인정보가 외부 AI API 로 나가는 경로(개인정보
보호법 제28조의8·제26조)를 보안과 맞닿은 갈래로 하나 둔다. 일반 보안 취약점 규칙은 쓰지 않는다.

## 결과

- 과제명과 연구 질문(정적 + AI 결합의 효과), 계획서의 주차별 기술 과제는 그대로다.
- 계획서의 '8유형' 약속은 지키지 않는다. 중간 보고서 1.3절에서 알리고 회신을 받는다.
- 정답 라벨에 법 해석이 들어가므로 라벨 지침과 비저자 검수가 더 중요해진다.
