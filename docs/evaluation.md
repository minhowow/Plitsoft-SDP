# 평가 설계 — 네 방식 비교

연구 질문(계획서 그대로): 정적 분석과 AI 검토를 결합하면 결과의 정확성과 이해도가 어떻게 달라지는가.

이 문서는 요약이다. 11/9 에 고정하는 분석 계획, 라벨 기준서, 표본 스크립트는 [../eval/](../eval/) 에 있고,
둘이 다르면 `eval/PROTOCOL.md` 가 맞다.

## 비교할 방식

| | 방식 | 설명 | 지금 |
|---|---|---|---|
| M1 | 정적 단독 | `--judge none`. 세 값 판정만 | 있음 |
| M2 | 정적 + AI 재검토 | 정적으로 '모름'인 곳만 AI 에 질문 1개(파일 1개) | 있음 |
| M3 | AI 독립 검토 | 정적 후보 없이 AI 가 의무 카탈로그를 보고 저장소를 검토 | 11주 |
| M4 | 결합(방향 A) | 정적 신호로 후보 → 에이전트형 판정 → 인용 관문 | 10주 |

## 표본과 정답

- 표본: 11/30 도구 고정 뒤 후보 스냅샷을 받고, drand 라운드 6688766(12/1 12:00 KST)의 값으로 40곳을 층별 추첨한다.
  광고 보류분 26곳을 더한다. 9/30 의 41개(dev 20 / test 21)는 개발과 예행에만 쓴다.
- 단위: (시작 파일, 정책). 라벨러는 시작 파일에서 출발해 같은 저장소의 다른 파일을 읽고 정답을 붙인다.
  주 지표는 (저장소, 정책) 쌍 단위로 센다.
- 정답: 도구를 보지 않는 LLM 라벨러 둘(서로 다른 모델)이 기준서대로 따로 붙이고, 갈리면 셋째가 정한다.
  저자가 아닌 사람 1명이 30개 단위를 눈가림으로 검수한다. 못 채우면 결과 제목에 '자기 평가'를 단다.
- 재현율은 도구와 무관하게 뽑은 단위로만 잰다(도구가 경고해서 더한 단위는 정밀도에만).
- 주 가설: 쌍 단위 F1 에서 M4 가 M1 보다 높다(저장소 부트스트랩 차이 구간이 0 을 넘는가).

## 지표

- 정밀도, 재현율, F1(쌍 단위가 주, 시작 파일 단위가 부). 저장소를 다시 뽑는 부트스트랩 95% 구간(2,000회).
- 근거 불일치: AI 가 낸 인용 가운데 관문이 거절한 비율.
- 비용: 단위당 호출 수, 입력·출력 토큰, 시간, 금액.
- 이해도(작게): 개발자 3~5명이 보고서만 보고 무엇을 고칠지 답한 정답률.

## 실행 도구 (고정 대상 밖, `eval/run/`)

고정한 `eval/` 파일(H0)은 고치지 않는다. 11/30 에 고정할 실행 도구는 `eval/run/` 에 둔다.

| 파일 | 하는 일 |
|---|---|
| `label.py` | 라벨러 한 명. 읽기 전용 도구 셋, 단위당 30번, 누적 비용 상한, 원 응답 보존, 인용 원문 확인. 갈린 단위를 주면 조정자로 돈다 |
| `adjudicate.py` | 두 라벨러를 합치고(카파), 갈린 단위를 조정 대상으로 내고, 조정 답으로 정한다 |
| `methods.py` | M1~M4 를 대기열 순서로 돌리고 비용 상한에서 멈춘다. 네 방식을 모두 마친 앞부분만 `prefix.json` 에 적는다 |

순서(12/1~): `units.py` → `label.py`(A, B) → `adjudicate.py merge` → `label.py`(조정) → `adjudicate.py merge --adj`
→ `methods.py` → 경고 단위 라벨(같은 순서) → `audit_sample.py` → 사람 라벨 → `compare.py`·`score.py`.
